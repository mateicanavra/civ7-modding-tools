# Civ7 Capability Realization Kind-Law Matrix

**Status:** Accepted target on the Habitat 0.5.2 consumer substrate
**Verdict:** `GROUND_PASSED`
**Date:** 2026-08-05
**Scope:** Kinds required by the selected capability-port topology only

## Purpose

This matrix defines the constructive boundary that must be accepted before any
destination law, generator, or source move in this initiative. It distinguishes
current Civ7 law from proposed generic law and assigns every invariant to its
native owner.

The selected shared direction is the released Habitat 0.5.2 consumer pack.
Magic Migration is executable prior art for selected-depth law, owner
separation, and migration proof. It is not a source of Civ7 roots, product
vocabulary, package manifests, or instance inventories.

## Reading The Matrix

- **Settled** means current accepted Civ7 law remains authoritative.
- **Proposed** means this packet selects a positive law that still requires
  Habitat admission and proof.
- A root grammar describes where a selected instance may live. Placement alone
  does not admit an instance.
- A selected root must satisfy its Habitat member/root grammar. Nx metadata may
  describe and schedule that project, but does not admit its architectural kind.
- `dist/`, `mod/`, `node_modules/`, generated runtime manifests, and
  `*.tsbuildinfo` are recognized output slots, not authored interiors or source
  authority. Blueprint-defined `habitat.toml` is instance authority, not output.
- A bare composition kind is not generable when a specialization is required to
  close its source interior.

## Shared Substrate And Qualified Gap

The accepted consumer authority is Habitat CLI release `0.5.2`, source
`92482052a7878d47085a14831bf3d6098f2b2d5d`, with canonical Template `main` at
`ee03d1c7e065c779fb63f9c57a1c0d2e121c1630`. Civ7 installs only
`@habitat-ai/cli@0.5.2`; its exact ordinary `@habitat-ai/sdk@0.5.2` dependency
supplies the shared policy pack.

The selected pack owns `app@1`, `package@1`, `plugin@1`, `plugin-nx@1`,
`provider@1`, and `resource@1`. Their manifests define instance anchors and
closed generic project shells. Ground proved clean and loose-member fixtures
for all six and an empty-write refusal for unsupported `service@1`.

This matrix therefore distinguishes two things:

- **shared kind authority**, which Civ7 consumes without copying; and
- **qualified product law**, which Civ7 authors locally only where a selected
  shared shell cannot express MapGen, CLI-topic, service, API, mod-family, or
  app-role semantics.

`service@1` is intentionally unselected. Current Civ7 service packets remain
local migration corpus and enforcement authority; they are not treated as
shared substrate. Native oRPC/Effect convergence remains an Interactive
product decision and must not be inferred from transitive dependencies inside
the Habitat SDK.

The product model remains authoritative for ownership and lifecycle. Qualified
host apps select providers and plugins, bind public clients, mount their native
hosts, observe, and release. API projections do not gain independent semantic
service authority. No generic runtime or profile layer is inferred from
Habitat's structural app shell.

Magic Migration remains executable corroboration, not a source of Civ7 roots,
instance inventories, or package names. No local producer, compatibility
facade, or copied shared structure is admitted because an existing Civ7 shape
is expensive to move.

## Kind-Owned Proof Topology

Proof structure is part of each blueprint's positive law, not a loose optional
directory and not an instance-by-instance naming choice. Each kind selects the
smallest disjoint confidence layers justified by its risks: public behavior,
contract/type exactness, external collaboration, lifecycle, projection,
assembly, or delivery. Test-only data and helpers remain beside the proof that
consumes them rather than forming a generic cabinet. A layer with no distinct
oracle is omitted rather than populated ceremonially.

The reusable confidence axes are:

| Axis | Oracle |
| --- | --- |
| Contract | Public type, schema, encoding, and error coherence |
| Semantics | Owner-specific value, error, and state outcomes |
| Execution | Lifecycle, isolation, ordering, cancellation, and once-only effects |
| Collaboration | Compatibility with one concrete external substrate |
| Projection | Faithful mapping between caller input/output and declared capability |
| Assembly | Exact members, host roles, bindings, and bootstrap plan |
| Delivery | Rendered artifact, currentness, placement, deployment, and live compatibility |

These axes decide who owns an oracle, not how many assertions to write.
Within an admitted leaf, cases remain risk-proportional and falsification-first:
they target durable public behavior, failure boundaries, and state transitions,
not implementation keys or coverage quotas. Exact source mirrors make public
command, operation, host, binding, and adapter subjects visible; they do
not require duplicating SDK guarantees or freezing every internal detail.

The selected proof constraints are below. A proof shape never admits its kind;
the state column remains authoritative:

| Kind | Admission state | Closed proof shape |
| --- | --- | --- |
| Package | Selected shared `package@1` plus qualified proof overlay where needed | Optional closed `test/contract/` and `test/semantics/` axes selected by exact component ids; at least one admitted axis is nonempty |
| Resource | Selected shared `resource@1` plus qualified proof overlay | Required `test/contract/contract.typecheck.ts`; optional colocated `contract.test.ts` only for runtime schema/failure values |
| Provider | Selected shared `provider@1` plus qualified proof overlay | Required exact `test/semantics/provider.test.ts` and `test/execution/lifecycle.test.ts`; optional exact `test/collaboration/provider.live.test.ts` only for real substrate compatibility |
| Standalone service | Established local Civ7 packet; shared `service@1` unselected | Required exact `test/contract/client.typecheck.ts`, operation-mirrored `test/semantics/modules/<module>/<operation>.test.ts`, and exact `test/execution/root.test.ts`; direct semantics suites are reserved for cross-module service invariants |
| Server API plugin | Selected shared `plugin@1` plus qualified API overlay | Required exact `test/contract/client.typecheck.ts` plus manifest-selected `test/projection/<component>.test.ts`; optional selected `test/execution/<component>.test.ts` only for API-owned scoped behavior |
| CLI topic | Accepted ownership; proof correction pending | Required `test/tsconfig.json` plus an exact source-derived mirror in `test/commands`; optional source-derived `test/adapters`; fixtures stay beside their consumer |
| CLI shell | Shared `app@1`; qualified CLI overlay pending | Exact `test/assembly/composition.test.ts`, app-binding/finalization execution proof, selected adapter proof, and one `test/tsconfig.json` |
| Web projection | `UNCONSTRUCTIBLE` candidate minimum | Required nonempty `test/views/*.test.tsx`; optional nonempty `test/interactions/*.test.tsx` and `test/execution/*.test.tsx` selected by the qualified product |
| App realization | Shared `app@1`; qualified host overlay required | Required closed host-composition and adapter execution axes plus one `test/tsconfig.json`; exact selected host and adapter identities determine proof leaves |
| Mod definition | `UNCONSTRUCTIBLE` candidate minimum | Required `test/definition.test.ts`; each qualified family packet closes its semantic layers; the selected map packet uses domain/module/artifact/operation/strategy and recipe/stage/step ownership |
| Mod realization | Accepted shared `app@1` root plus qualified local overlay | Required closed `test/artifact/*.test.ts`, `test/deployment/*.test.ts`, `test/runtime/{*.fixture.ts,*.test.ts}`, and `test/live/*.live.test.ts`; currentness, deployment, compatibility, and live remain distinct Nx targets |

All proof directories are closed. `*.fixture.ts` or `*.fixture.tsx` may live
only beside the suites that consume them and are never suites. There is no
generic `support`, `shared`, `behavior`, `mechanics`, or `integration` cabinet;
those names are admitted only when a kind gives them one unambiguous oracle.

Closed layer grammar is not proof membership. Each kind also names the
authority that selects its finite proof leaves. A source-shaped kind may
require an exact source-to-proof mirror; an app mirrors admitted hosts and
adapters; a product-qualified kind records exact proof-component identities
in its instance manifest or an already-authoritative product manifest.
An instance may select members only inside its kind's declared confidence
axes; it cannot invent another layer or redefine the oracle for an existing
one. Selection changes the finite subjects proved inside an axis, never the
testing strategy itself.
`structure.toml` permits only the selected layer grammar, and bounded source
relations require one matching leaf for every selected identity while
forbidding unselected leaves. A `*.test.*` wildcard is therefore only the
terminal filename grammar inside a selected layer, never discovery authority
or permission to invent proof case by case.

Generic kinds use reusable proof layers. Domain-qualified kinds may replace
those layers with a stronger domain grammar where the subject demands it:
MapGen definition proof follows domain/module/artifact/operation/strategy and
recipe/stage/step ownership rather than being flattened into generic package
tests. A qualified proof law may narrow or add to its parent, but never leave
`test/` open, duplicate provider guarantees in consumers, or preserve tests
whose only subject is superseded wiring.

An already admitted kind outside this matrix keeps its accepted qualified proof
grammar; it does not inherit an arbitrary row by analogy. If that kind admits a
`test/` root without closing its internal confidence layers, the kind is not
sealed and generation must remain refused until its proof law is completed.

## Decision Gates

### T1: Nx Role Vocabulary

The current Civ7 Nx taxonomy uses domain-shaped primary tags such as
`kind:control`, `kind:adapter`, `kind:plugin`, and `kind:mod`. The shared
substrate uses structural `type:*` facts plus orthogonal role, surface,
resource, provider, and product/capability facts. Civ7's current vocabulary
cannot select this topology without ambiguity:

- current `kind:plugin` means reusable helper packages, not projections;
- current `kind:adapter` exclusively owns Civ7 engine-global access;
- current `kind:control` combines resource, service, and host concerns.

The target graph vocabulary follows the shared convention:

| Structural type | Required qualifying facts |
| --- | --- |
| `type:package` | an accepted `layer:*` or shared-model role when proven |
| `type:resource` | `resource:<resource-id>` |
| `type:provider` | matching `resource:<resource-id>` and `provider:<provider-id>` |
| `type:service` | one product, capability, or domain identity |
| `type:plugin` | the selected role/surface specialization |
| `type:app` | one product/runtime identity; optional product and capability graph facts |

These facts describe project role and graph policy. They do not admit a Habitat
kind, select source topology, or replace blueprint membership. Gate T1 closes
when the target table, complete dependency matrix, workspace project metadata,
and graph proof are accepted together. Reusing current `kind:plugin`,
`kind:adapter`, or `kind:control` as a local graph exception is rejected.
Nx targets schedule concrete entrypoints. The qualified app packet owns plugin
and provider selection plus host-role composition; no descriptor or profile
object is required by shared `app@1`.

### T2: Instance Admission Carrier

The current Habitat ontology requires exactly one blueprint-defined instance
manifest, normally `habitat.toml`, at every admitted instance anchor. No
manifest means no admitted instance. Each accepted blueprint packet must
therefore define:

- its anchor grammar and manifest location;
- the blueprint id and version facts;
- every governed root for single-root, nested, or composite instances;
- allowed capability and niche facts;
- validation and migration behavior.

The instance author materializes those facts; Habitat admits them and Nx
corroborates graph identity and schedules proof. Existing locked CLI path
selectors remain operative for the already-present shell and topic corpus, but
this initiative does not treat them as a generic admission bridge.
Every new instance of a selected shared kind waits for its manifest-bearing
packet. `service@1` is not selected in Habitat 0.5.2, so current Civ7 services
are governed by an explicit local compatibility rule set and do not pretend to
be `package@1` instances. They gain `habitat.toml` only when shared service
authority is published and adopted. Exact Civ7 service inventories remain in
qualified product law, never generic structure.

### T3: Construction Interface

Habitat 0.5.2 exposes the workspace `init` and `remove-hook` generators. It does
not promise a generic project generator, and Civ7 does not recreate one as
local substrate. A product slice may use ordinary Nx generation, a bounded
product template, or direct construction. A selected shared kind is admitted
only when the complete destination and its blueprint-defined `habitat.toml`
arrive together. An explicitly unselected compatibility kind instead requires
its complete local rule application and may not manufacture a false manifest.

Construction refuses before product source moves when the kind is unselected,
the qualified overlay is missing, the manifest names unsupported facts, or the
closed destination would leave loose members. Tool convenience never becomes
admission authority.

## Package Project

**State:** Shared `package@1` shell selected; qualified package semantics remain
product-owned.

Habitat 0.5.2 supplies the generic closed package shell. The shape below
describes Civ7's selected package role and any stronger qualified proof, not a
replacement for the shared blueprint.

**Selected depth and root grammar**

- One Nx project rooted at `packages/<package>`.
- Package kind is selected explicitly; it is not inferred for every current
  directory below `packages/`.
- This topology selects no package instance merely to adapt a service or carry
  an oRPC contract. A package owns portable pure protocol, SDK, algorithm,
  schema, mechanics, or support matter with no managed lifetime or product
  policy.

**Required spine**

```text
habitat.toml
package.json
project.json
src/
  index.ts
tsconfig.json
```

`src/` is closed to exact `index.ts` plus optional direct lower-kebab `.ts`
leaves. It admits no child directory. A semantic child collection requires an
independently selected narrower kind rather than recursive generic package law.
Additional file types require a qualified niche.

**Finite optional authored interiors**

```text
AGENTS.md
README.md
test/
tsconfig.paths.json
tsconfig.test.json
tsconfig.tools.json
tsconfig.tsup.json
tsup.config.ts
vitest.config.ts
bunfig.toml
```

Recognized output slots are `dist/`, `node_modules/`, and
`tsconfig.tsbuildinfo`.

A package-owned tool or script interior requires an independently selected
closed tooling kind. Generic package law does not admit `scripts/` as an open
escape hatch.

**Public face and import direction**

- `package.json.exports` exposes only deliberate entries rooted in `src/`.
- `src/index.ts` is the default public entry; additional subpaths point to
  named semantic owners, not broad barrels.
- A plain package consumes only other public package surfaces.
- A package may expose genuinely reusable non-oRPC vocabulary or pure
  mechanics. It never authors or re-exports a service-owned oRPC contract.
- Packages never import resource contracts, providers, services, plugins,
  apps, private source, or generated output.
- Packages never read or mutate ambient process, filesystem, network, engine,
  or host state. Path injection and one-shot execution do not turn an external
  effect into pure package mechanics. A package may parse bytes, derive plans,
  compare snapshots, or serialize values supplied by its caller; a qualified
  runtime adapter performs the effect.

**Proof topology**

If `test/` exists, it is nonempty and closed to optional nonempty
`contract/` and `semantics/` axes. Contract contains `*.typecheck.ts`;
semantics contains `*.test.ts`. The instance manifest selects a finite list of
lower-kebab proof-component ids in each admitted axis, and each selected id
requires exactly one matching leaf. At least one axis and one component are
selected. Unselected leaves are forbidden. Colocated `*.fixture.ts` is allowed
only beside its consuming suite. Structure, reachability, and task wiring
remain Habitat, Knip, and Nx proof rather than package suites.

**Nx mapping**

- Candidate graph metadata: `type:package`.
- Optional secondary: an accepted role such as `role:shared-model` or
  `role:pure-mechanics`.
- A service or runtime adapter is not an admitted package role. The current
  engine-global `kind:adapter` project is migration corpus: its portable port,
  static metadata, and mock may remain package-shaped, while its Civ7-global
  implementation moves to the qualified mod realization.

**Generator**

Unsupported today. After law acceptance, add a package scaffold that writes the
required spine and no product vocabulary. It must not generate a service
adapter, filesystem implementation, or parallel oRPC contract. Any retained
mod-install, save-file, or Studio-run package selects this kind only for its
pure plan, parser, schema, hashing, serialization, or comparison surface.

- Resource projects may depend on `type:package`; no project may depend on a

**Generator**

## Service Source And Standalone Semantic Service

**State:** Accepted local compatibility law while shared `service@1` remains
unselected. The inspected baseline and existing Civ7 service are migration
evidence, not destination authority.

**Selected depth and root grammar**

- The local compatibility law governs standalone roots at
  `services/<service>` and their private `src/service` implementation.
- It is not a local Habitat blueprint, a copy of the dormant SDK packet, or a
  `package@1` specialization. Rule selection remains explicit through the
  owning Nx project until shared service authority replaces it.
- A server API owns a distinct qualified projection packet. It may use the
  same architectural ideas, but it does not inherit domain-service law or
  private service source.
- The private implementation owns no proof interior. The standalone service
  project owns contract, semantics, and execution proof.

**Required standalone spine**

```text
  client.ts
  service/
```


The selected `modules/` collection is closed, nonempty, and admits only

The selected Civ7 service instances close that generic collection to exact
semantic inventories:

```text
civ7-control -> {app,game,map,ui}
civ7-play -> {attention,automation,city,diplomacy,notifications,
```

Within control, `game` owns setup/start and current-game facts. `map` separately

Root middleware contains direct kebab-case `.ts` leaves with no index or nested

No generic `shared`, provider, transport, host, runtime, source-owned proof, or
additional service-root cabinet is admitted. Recognized outputs are `dist/`,
`node_modules/`, and `tsconfig.tsbuildinfo`.

**Public face and import direction**

- `src/client.ts` is the complete public caller and construction face. It
  accepts app-supplied ready capabilities and maps them into the
  service's private module ports.
- `src/service/**` is private implementation.
- Services consume app-supplied ready ports and public package types.
- A service may consume another service only through that owner's public
  `src/client.ts` face. `civ7-play -> civ7-control` is the selected semantic
  direction; private contracts, routers, implementation types, and the
  control service's ready resource context remain inaccessible.
- A service may declare a named semantic capability in its public construction
  face without importing the project that realizes it. That public dependency
  descriptor owns the adapter operation signatures and typed failure
  vocabulary. A qualified consuming app may directly construct one adapter
  implementing that descriptor and pass the ready value to the public client
  constructor. The adapter may compose public definition faces and pure
  packages while owning its app-qualified host effects; it never imports
  another app to obtain an implementation. Habitat closes the selected adapter
  identity and import/proof topology, and TypeScript proves descriptor
  assignability. No shared runtime, execution-descriptor compiler, facade, or
  private cross-app import participates in construction.
- A service client may type its ready input through the matching public
  resource contract and may consume its own private port types. It imports no
  provider implementation.
- Services import no projection plugin, app, transport mount, ambient Civ7
  global, or generated output.
- Standalone-service-scoped actors, records, transition policy, cancellation
  state, retention policy, and finalizers remain private service model or
  module implementation. They do not become a resource unless they manage a
  foreign acquired capability through a provider-neutral contract. An
  API-selected projection packet admits none of that semantic service state.
- The private implementation owns typed oRPC context and Effect dependencies;
  public callers never receive an ambient runtime or service locator.
- Every Effect-authored operation crosses into its native oRPC procedure once,

descendants is lifted to the nearest common admitted owner's exact `setup.ts`;
free-form `fixtures/` cabinets are forbidden. Root `test/setup.ts` owns only
suite-wide switchable Civ7 preset, map-seed, game-seed, and generic test-kit
composition. `recipes/<recipe>/setup.ts` may own one recipe-specific bootstrap
for its stages, steps, metrics, parity, trace, and visualization proof. Tests
whose subject is a shared default opt out explicitly rather than mutating it.

Generic `generated`, `scripts`, `support`, `runtime`, `operations`, and
`recipe` test cabinets are excluded. Generated output and command proof belong
to the realization or another independently selected kind. Live parity is
selected by the recipe but executes through the realization-owned live target;
live game loading remains realization proof. Structural SDK guarantees are not
repeated as product behavior. Civilization definitions require a separately
accepted finite content and proof grammar.

**Nx mapping**

- Observed graph metadata may describe `type:plugin`, a mod-definition
  role/surface, and one family identity. These facts do not admit the Habitat
  packet.
- Current `kind:mod` is replaced only when T1 and the definition/realization
  dependency directions are accepted.

**Generator**

Product authoring is explicitly refused today. The candidate shape is not
Engineer input. After a qualified family law is accepted, generation requires
that family and emits no authored product content beyond an empty typed
definition shell.

## Mod Realization Project

**Public face and import direction**

## Habitat Engineer Handoff Contract

**Rule owners**

- Habitat `structure.toml`: every required spine, finite optional interior,
  protected generated slot, and absent legacy interior.
- Habitat Grit: bounded public/private imports, provider/resource direction,
  single stable service implementation ownership, projection/app direction,
  and definition/realization direction. It does not infer vendor construction
  or error behavior from syntax.
- TypeScript plus `package.json`: public faces, exact assignability, native
  router completeness, context/failure types, and package or package-less
  resolution.
- `lintEffect` plus execution proof: exact installed-lane Effect context/error
  discipline, once-only native adaptation, declared error projection, defect
  sealing, cancellation, and middleware/bootstrap order.
- Instance manifests: blueprint identity/version, governed roots, selected
  capabilities, and accepted niche facts.
- Nx: primary and secondary facts, project dependency matrix, target ordering,
  generation/currentness, deployment, and uncached live proof.
- Tests: the kind-selected contract, semantics, execution, projection, assembly,
  or delivery layers and their observable oracles.

This matrix is not one broad Engineer corpus. Each selected law or product cut
receives a separate handoff containing:

- exact rule files or accepted upstream packet commit;
- exact blueprint-defined manifest anchor;
- exact source roots and exact destination roots;
- one terminal disposition for every source row: `relocate`, `inline`,
  `combine`, or `delete`;
- preserved behavior and focused proof owner;
- explicit adjacent roots excluded from acquisition.

Umbrella roots such as `packages/**`, `resources/**`, `services/**`,
`plugins/**`, or `apps/**` are forbidden handoff inputs. Alternative
destinations and “after semantic review” rows remain design corpus and cannot
reach an Engineer. A shared blueprint absent from Civ7 is corrected upstream,
accepted at a successor Template commit, then imported rather than re-authored
from current residue. Package, Studio web/app, civilization mod
definition/realization, and their proposed Habitat roots remain design inputs
until their own accepted closed packets and manifest anchors exist.

**Proof classes**

1. Positive and negative injected structure fixtures for every closed scope.
2. Grit match/no-match fixtures for each bounded source relationship.
3. TypeScript compile-only fixtures for public faces, router completeness,
   context, and exact failure channels.

## Admission And Seal Order

Each reusable law packet proves its positive shape before product relocation,
then is promoted in the exact branch that burns its admitted corpus down:

```text
authority
  -> positive generic law
  -> closed topology
  -> bounded source relationships
  -> injected fixture proof
  -> promote and enforce in the burn-down branch
  -> exact live red corpus
  -> qualified relocation, inlining, combination, or deletion
  -> zero
  -> behavior proof
  -> seal and land
```

One product cut may keep several laws and instance migrations coupled where
lifecycle and consumer closure require it:

```text
fixture-proved destination laws
  -> Nx mapping and selected shared-instance manifest generation
  -> generator contract and refusal proof
  -> promote exact laws
  -> live red
  -> qualified dispositions
  -> zero and runtime proof
  -> seal and land
```

Provider waits for resource. API source waits for its shared plugin root and
qualified API packet while consuming domain capabilities only through public
clients. Qualified apps wait for their local host-composition packets.
Mod realization waits for mod definition. No later row weakens or bypasses an
earlier row's public/private boundary.

## Stop Conditions

Stop and return to design if:

- T1 cannot describe a project with one structural type plus orthogonal graph
  facts without assigning kind admission, plugin membership, provider
  selection, or process-role selection to Nx;
- a kind requires an instance name or current file inventory in generic law;
- a selected shared-kind instance has no accepted blueprint anchor or generated
  `habitat.toml` facts, or a local compatibility kind pretends to have them;
- a required child remains structurally open after all selected
  specializations apply;
- a package role becomes a substitute for a missing resource, service,
  projection, or app kind;
- a service or API projection duplicates contract authority, imports private
  service source, or reintroduces a facade;
- a definition law admits generated realization output;
- an app or plugin starts exporting reusable domain truth;
- a provider, service, or plugin selects its own runtime lifetime;
- a generator needs to write source before the accepted law and Nx mapping can
  validate the resulting tree.
