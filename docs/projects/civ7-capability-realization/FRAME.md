# Civ7 Capability Realization Frame

**Status:** Model Ground ratified; Controller Foundation admission active
**Date:** 2026-08-06
**Owner:** Civ7 migration director

## Intent

Realize the existing Civ7 modding platform on the shared Habitat substrate by
moving complete product capability chains into their rightful owners. The
migration must remove compensating mechanisms and false containers rather than
preserve them under cleaner names.

The unit of analysis is a product capability realization chain:

```text
actor outcome
  -> semantic authority
  -> public relationship
  -> qualified realization
  -> independent proof
```

Current directories, imports, contracts, and tests are evidence. They are not
authority by themselves.

## Rolling Focus

**Attractor cubes**

- Meaning: Actor. Intent. Outcome. Refusal. Trust.
- Structure: Owner. Boundary. Direction. Lifecycle. Closure.
- Descent: Ground. Chain. Ratchet. Delete. Seal.

**Current frame:** the actor/outcome, product, system, topology, source, and
public-surface models are ratified. The exact pre-substrate estate at
`fd60a16ad7605ad34c8afa9668aa847b52931022` remains behavior evidence; later
transition code and the deleted controller island remain non-authoritative.
Construction now proceeds only through the accepted five-part separation:

1. generated official Civ7 API knowledge;
2. a TypeScript controller service executing inside shell/game App UI realms;
3. host access through a managed Tuner capability and app-bound typed link;
4. actor-facing Play policy over the public controller client; and
5. an explicit, protected raw-JavaScript diagnostic escape hatch.

The controller is realized as a Civ7 mod. Mature operations do not cross Tuner
as generated JavaScript bodies. Tuner transports a bounded typed envelope to a
versioned realm-local controller ingress. Play owns intent, reconciliation,
no-repeat, and next action. The controller owns native observation, checks,
at-most-once dispatch, and exact engine evidence.

**Current container:** seal active repository guidance against the ratified
model, then turn the smallest complete Controller Foundation chain structurally
red. The first constructed vertical is generated official API authority ->
identity/ping service kernel -> controller mod realization -> app-bound typed
ingress -> live realm proof. Existing host-injected operations remain only in
the finite transition quarantine and receive no new mature behavior.

The in-engine boundary is a production-project closure, not the mod app.
Container 1 activates `runtime:civ7-v8` atomically with its first complete
project and executable rules; it admits only same-tagged project dependencies
and a proved positive vendor set, while qualified source law refuses `node:`
and `bun:` imports. Build, install, Tuner binding, and live proof remain in
untagged host apps. Mixed projects split rather than weakening the closure.

**Authority order:** actor outcome -> product authority -> execution realm ->
relationship direction -> Habitat kind -> public contract -> app composition ->
behavior proof. The existing working tree may not outrank any earlier item.

**Stack boundary:** this initiative operates only on the single linear Graphite
line from `agent-root-civ7-habitat-051-ground` to the current
`agent-root-civ7-live-refusal-ground`. The Fluree branches and worktrees shown
beside it are separate parked workstreams and are neither edited nor restacked
by this initiative. No parallel Civ7 implementation branch is admitted.

**Ground:** Habitat `0.5.2` is the locked consumer substrate for shared
`app@1`, `package@1`, `plugin@1`, `plugin-nx@1`, `provider@1`, and `resource@1`.
Civ7 consumes those laws and keeps only qualified instances, overlays, policy,
adapters, and product proof. Shared `service@1` remains unselected, so service
construction is refused until Habitat publishes it. Existing local generic
service patterns are migration substrate, not a Civ7-owned substitute.

**Official realm evidence:** shell, loading, and game have distinct document
roots, and shell/game scoped UIScripts are supported. The exact Tuner-observed
global lifecycle across those transitions remains unproven. The controller
probe must record whether identity is absent, retained, or replaced at every
phase. Tuner state IDs are runtime-discovered. `CMD` Promise behavior and later
global visibility are also proof gaps; no mailbox or mutating asynchronous path
is selected until the discriminating live experiment runs.

**Current gradient:** guidance seal -> destination law red -> official API
authority -> controller kernel -> controller mod -> typed ingress -> live realm
proof -> native verticals -> Play -> projections -> direct-control deletion ->
remaining platform chains -> full seal.

This is not a backlog. Work emerges from the difference between the normative
models and the observed estate. Once a difference closes, it disappears from
the frame.

## Settled Evidence

- The baseline capability corpus preserves CLI discovery, Tuner framing and
  epochs, explicit diagnostics, semantic action outcomes, Studio one-host/run
  behavior, official-data currentness, exact mod deployment, and deterministic
  Swooper generation.
- `packages/civ7-direct-control` mixes socket/session lifecycle, raw execution,
  generated native JavaScript, observations, setup, OS capture, and convenience
  views. It is not a valid product owner.
- The baseline control service is Play-heavy in substance: it owns actor
  admission, polling, reconciliation, no-repeat, priorities, and next action.
- Official Civ7 resources prove shell/game scoped UIScript loading and separate
  document lifecycles. A bootstrap must explicitly publish a callable global.
- The current `civ7-types` surface is partial and contains a wildcard `any`;
  systematic state-scoped API generation is not yet complete.
- The current Studio live attempt proved exact generation and installation but
  not startup or map behavior. A manual new-game attempt also reached a map
  generation error. Those are open product proofs, not reasons to preserve the
  current architecture.

## Exterior

- No source migration while the corrected model packet is internally
  contradictory.
- No deleted controller implementation as reference.
- No automatic live mutation merely because Civ7 is running.
- No broad HQ API, workflow, catalog, desktop resource, or network Play API
  without a concrete caller or lifecycle.
- No local Habitat fork or copied shared law.
- No parallel implementation stack.

## Falsifiers

Reframe if exact evidence proves that the controller cannot be loaded and
invoked across required Civ7 realms, that mature native behavior cannot be
separated from host or actor policy, that the selected owner graph requires a
cycle, or that an admitted Habitat kind cannot express a necessary lifecycle
without violating its authority.

Product, System, Outcome, and Actor/Outcome agree; baseline capabilities have

ownership contradiction. Live Controller Foundation evidence remains a
